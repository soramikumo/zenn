## 概要

普段の作業は MacBook でしています。家には Windows のデスクトップもあります。

この Windows を常時起動の「実行マシン」にしました。Mac とはファイルを共有していて、SSH でお互いに操作もできます。さらに Slack からメンションすると、Windows の Claude Code が動いてスレッドに返事などの仕組みを作ったので、まとめています。

一応
Loop Engineering は、AI に毎回指示を出すのをやめ、指示を出す仕組みのほうを作る考え方です。この記事では、その土台になる「常時起動の実行マシン」と「入口」を作ります。

今回は高難易度なループはせず、claude routineでも代用できます。ただclaude routineには制限があるのですが、そういったものを取り払えるようになっています。(自前で作っているため)

伝えたいこと3点

1. 2台が「お互いに共有・操作できる」状態になると、OS やハードの違いは気にならなくなる
2. 常時起動のマシンで claude -p を呼べば、API キーなしでも Claude の自動化ができる
3. 入口と出口だけ差し替えれば、同じ仕組みが使い回せる

それぞれを深掘って行きます。

## 1. 2台がお互いに共有・操作できる
![](https://static.zenn.studio/user-upload/906eb174c8fb-20261014.png)
Mac と Windows をつなぐ経路は3本です。

- Syncthing：決めたフォルダを双方向に同期します。同じ LAN にいる時だけ同期されます。
- SSH：両方向に鍵認証で入れるようにしました。Mac の Claude から Windows を操作でき、逆もできます。
- Parsec：人間が画面を見て操作する時に使います。お互いのpcからGUIで操作することが可能になります。

ポイントは経路の使い分けです。コマンドで操作する Claude は SSH、画面を見て操作する人間は Parsec と分けています。

お互いに操作できると、片方にしかない力も借りられます。たとえば Claude は画像を生成できません。一方で Windows には GPU が載っています。画像生成のモデルを入れれば、専用サービスに質で劣っても画像を作ることはできます。(Geminiを使えばいいが)

Mac単体でできなかった作業が自然言語で別のハードを操作できるようになることで、以前より解決できる問題の種類/可能性を広げられたかなと思っています。

同期するフォルダは GithubとSyncthingで管理しています。注意としては.git は Syncthing の対象から外しました。2台が同時に .git を書き換えると壊れやすいっぽいです(claude曰く)

:::details なぜ .git を同期すると壊れやすいのか
git は「.git を書き換えるのは自分ひとり」という前提で動いています。Syncthing はその前提を崩します。

ファイルが1つずつ、少し遅れて届く
1回の commit で、git は複数のファイルをまとめて書き換えます。中身の入ったオブジェクトや、ブランチの先頭に当たる refs/heads/main などです。Syncthing はこれらを1ファイルずつ送ります。そのため相手側には「ブランチは新しい commit を指すのに、中身はまだ届いていない」瞬間が生まれます。この状態で git を触ると bad object などのエラーになります。

両側で commit すると片方が消える
2台でそれぞれ commit すると、refs/heads/main が両側で別の値になります。Syncthing は中身をマージできません。片方だけ採用し、もう片方は .sync-conflict という別名のファイルに逃がします。結果として、どちらかの commit がブランチから外れてしまいます。

ロックファイルまで届く
git は作業中に index.lock などのロックファイルを作り、終わったら消します。これが相手側に届くと、相手の git は「ほかの git が作業中だ」と判断して止まります。

掃除が相手の邪魔をする
git gc はバラバラのオブジェクトを1つのファイルにまとめ、元のファイルは消します。この削除まで同期されると、相手側でまだ使っていたファイルも消えかねません。

git の作業ディレクトリは1か所に決め、もう1台とは push と pull でやりとりするのが安全です。
:::

ひとつハマったのは Windows 版のClaude のデスクトップアプリから Syncthing を設定したところ、再起動後に設定が消えました。ストアアプリ形式のため、AppData\Local への書き込みはアプリ専用の場所に振り替えられていました。
最終的に Mac から SSH で入り、元の設定を本来の場所へ戻して直しました。(claudeの自己修復)

## 2. スマホから頼んで、Windows の Claude が返す
![](https://static.zenn.studio/user-upload/96886de92429-20261014.png)
Slack bot は Socket Mode で動かしています。Windows から Slack へ先に WebSocket をつないでおく方式です。自宅のルーターに穴を開ける必要はありません。

流れは次のとおりです。

1. 起動時に Windows から Slack へ接続しておく
2. スマホの Slack から bot にメンションする
3. bot は送信者を確かめ、本人なら 👀 で反応する
4. メンションの本文を claude -p に渡す
5. 返ってきた答えをスレッドに投稿する

Slack のスレッドと Claude のセッションは1対1で対応させました。最初の投稿で --session-id を発行し、同じスレッドの続きは --resume で再開することもできます。
スレッドで話し続ければ、Claude も前の話を覚えています。

例：「このPCのホスト名を教えて」と送ると、7秒ほどで返事が来ました。bot はタスクスケジューラに登録したため、Windows を起動すれば勝手に立ち上がります。
![](https://static.zenn.studio/user-upload/9fedddf5fd5d-20261014.png)

### claude -p の特徴

claude -p は Claude Code を対話なしで1回だけ動かすモードです。
中身はふだん使っている Claude Code と同じです。

- 作業フォルダの CLAUDE.md やスキルを読む：どのフォルダで起動するかで、Claude の知識と振る舞いが変わります。
- ツールが使える：ファイルの読み書きやコマンドの実行もできます。チャットで答えるだけではありません。
- 会話を続けられる：--session-id で始めた会話は、--resume で続きから再開できます。
- 指示を足せる：--append-system-prompt で bot 用の注意書きが追加できます。
- 確認を飛ばせる：--dangerously-skip-permissions を付けると、ツールごとの許可確認が出ません。bot の向こうには許可を押す人がいないため、このオプションは必須です。

bot の中身

bot は170行ほどの Python ファイル1つです。Slack Bolt で受け取ったメンションを、次のように claude -p へ渡しています。
```python
cmd = [CLAUDE, "-p", prompt, "--dangerously-skip-permissions",
       "--append-system-prompt", SYSTEM_NOTE, *session_args]
env = {**os.environ, "SLACK_CHANNEL": channel, "SLACK_THREAD_TS": thread_ts}
r = subprocess.run(cmd, cwd=WORKDIR, env=env, capture_output=True,
                   encoding="utf-8", timeout=TIMEOUT_S)
```

SYSTEM_NOTE には bot 用の注意書きを入れました。

- スマホで読むので短く答える
- Slack の書式で崩れない書き方にする
- ファイルは添付用のスクリプトで返す

返信先のチャンネルとスレッドは環境変数で渡すため、Claude が自分で今のスレッドにファイルを添付などもできます。

### 個人のナレッジを参照させる

cwd=WORKDIR で指定している作業フォルダが肝です。ここには life-mi_queue という個人用のナレッジを置いています。個人の契約書や家計の分析、月ごとの振り返りなどを Markdown でためたフォルダです。Mac と Syncthing で同期しているため、Windows でも同じ中身が読めます。

Claude はこのフォルダで起動するため、自分の事情を知ったうえで答えてくれます。「先月の支出で多かったものは？」と聞けば、家計のファイルを読みに行きます。

日々考えていることも Slack にためています。bot経由なら、スマホしかない場面でも自分のナレッジをふまえた深い話ができます。人には話しにくい内容でも、手元の記録を見ながら一緒に考えてくれる相手になります。

### ファイルや HTML も受け渡せる

返事はテキストだけではありません。Claude が作ったファイルや HTML・スクリーンショットも、スレッドに添付して返せます。HTML はアーティファクトとして共有する方法もあります。外出先で作らせた資料を、そのままスマホで確認できるわけです。

### チャットアプリとの違い

Claude のチャットアプリとの一番の違いは、手元の PC で動くことです。自分のファイルを読み書きでき、コマンドも実行できます。結果はファイルで返せます。

bot を何個でも作れる点も大きいです。作業フォルダや注意書きを変えれば、役割の違う bot ができます。ナレッジ相手の bot や PR レビュー用の bot・家計用の bot というように分けられます。チャットアプリより手間はかかりますが、できることの幅はずっと広いと感じています。

## 3. 入口と出口を差し替えて使い回す
![](https://static.zenn.studio/user-upload/e9f2ddac9d34-20261014.png)
真ん中の「常時起動のマシンで ```claude -p``` を呼ぶ」部分は変わりません。差し替えるのは入口と出口だけです。

- Slack のメンション → スレッドに返信（今回作ったもの）
- GitHub の新しい PR → PR にレビューコメント
- 決まった時刻 → レポートを投稿

たとえば PR レビューなら、CI のジョブから実行マシンを呼ぶ形で作れます。社内 LAN の中だけで受け付ける API を実行マシンに用意し、Webhook で呼んでもかまいません。インターネットへ入口を出さずに済むため、社内 LAN 上の GitLab のような環境で活躍できそうです。
> GitHub なら公式の claude-code-action があるので、わざわざこの形にする必要はないかなと思います

ただし ```claude -p``` は Anthropic の API と通信するため、インターネットから完全に切り離された環境では動きません。API を用意するなら、呼び出し元を確かめるトークンも忘れずに入れます。全権の Claude が動くため、LAN の誰でも呼べる状態は危険です。

claudeのデフォルト機能であるコネクタでは、googleアカウント1件やslackワークスペース1つしか結びつけられないなど、制限がありますが、この仕組みなら自前でmcpを組まずに実行マシンが自前のアカウントを確認できるので、複数個のメールアドレスを見に行ったり、アンソロピックが対応できないもの(銀行システムなど)にアクセスし、レポートを作ることができます。

## 私の見解

一番大きいのは、API の従量課金なしで Claude を自動化できる点です。ログイン済みの Claude Code を呼ぶだけのため、Routines のような実行回数の上限にも縛られません。

ただし制限が消えるわけではありません。サブスクリプションの利用上限はそのまま残り、手元で使う分と同じ枠を分け合います。Anthropic の規約も、個人が自分のために使うことを前提にしています。他人に使わせたりサービスにしたりするなら、API キーを使うべきです。

### セキュリティ面
セキュリティの面では、家のルーターに穴を開けていない点が大きいです。Syncthing と SSH は LAN の中だけで動き、bot も Windows から Slack へ外向きにつなぐ形です。
外から直接たたける入口はありません。

ただし外から操作できる経路はゼロではありません。Slack と Parsec のアカウントがそのまま入口になります。今の bot の Claude は全権を持っているため、Slack のアカウントを乗っ取られると Windows も操作されます。SSH で Mac にも入れるので、被害は2台に広がります。
bot は自分のメンションにだけ反応させていますが、Slack と Parsec には2段階認証も設定しておくべきです。(それで防げるかはさておき)

### まとめ

今回は余っているデスクトップpcを使ってmacから操作 && お互いに操作できる環境を構築しました。

単純にお金があればクラウド環境で構築するのが理想ですが、あえて物理デバイスでやってみたかったので、こういった構成にしています。

今の bot は、自分がメンションするたびに動いています。図3の「決まった時刻」や CI を入口にすれば、人が声をかけなくても回るループになります。もちろん、人が声をかける入り口を作るのも大事です。

今後としてはwindowsに搭載されたgpuを使って機械学習系の操作をmacを通して遊んでみたり、家電含めてiotにして連携デバイスを増やすことでmacとclaude(自前LLMでも可)で自然言語で操作できる環境を構築していくのも面白いなと妄想しています。

## 使ったツール
| ツール | どこで | 何をするものか |
| --- | --- | --- |
| Claude Code | Mac・Windows | ターミナルで動く Claude。`claude -p` で対話なしに1回だけ動かせる |
| Syncthing | Mac・Windows | フォルダを端末どうしで直接同期する。クラウドを通さない |
| OpenSSH | Windows | Windows 標準の SSH サーバー。設定の「オプション機能」から入れられる |
| Parsec | Mac → Windows | 画面を転送して遠隔操作する。遅延が少なく、外出先からもつながる |
| Amphetamine | Mac | Mac のスリープを止める。蓋を閉じても同期や SSH が切れないようにする |
